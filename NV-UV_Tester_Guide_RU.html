⚡Что такое NV-UV?

NV-UV — инструмент для undervolting современных видеокарт NVIDIA: RTX 50 Series (Blackwell), RTX 40 Series (Ada) и, начиная с v0.98, RTX 30 Series (Ampere). Он упрощает процесс undervolting, который обычно требует ручного редактирования кривой в MSI Afterburner.

NV-UV использует Afterburner как backend, поэтому должны быть установлены MSI Afterburner + RTSS.

🔧Установка

ВАЖНО, не пропускайте: чтобы NV-UV мог читать и записывать напряжение GPU, в Afterburner нужно включить несколько параметров. Без этих настроек NV-UV показывает 0 mV, V-Лок применяется некорректно, а scanner выдаёт неправильные результаты. Шаги 1 и 2 ниже обязательные, а не optional.
1
Prepare Afterburner, General Tab
AB Settings (⚙), вкладка General:
Выберите вашу NVIDIA GPU в поле Master graphics processor selection

Включите эти флажки:
✓ Enable hardware control and monitoring
✓ Enable low-level IO driver
✓ Enable low-level hardware access interface → user mode
✓ Unlock voltage control → standard MSI  ⬅ критично
✓ Unlock voltage monitoring  ⬅ критично

Нажмите OK (не Cancel!) и перезапустите Afterburner.
2
Prepare Afterburner, Monitoring Tab
Settings (⚙), вкладка Monitoring. Прокрутите длинный список sensors и включите:

✓ GPU voltage  ⬅ без этого нет V-Лок
✓ GPU power

Нажмите OK и перезапустите Afterburner.

Проверка: в главном окне AB поле "VOLT" теперь должно показывать реальное напряжение (например, 905 mV) вместо 0 mV. Если там всё ещё 0, AB не принял изменение — вернитесь к шагу 1 и убедитесь, что оба параметра Unlock действительно включены.
Примечание для Reference-Design RTX 5090: на некоторых reference-картах Afterburner иногда сам сбрасывает флажки Unlock. Если через некоторое время показания напряжения внезапно падают до 0 mV, просто повторите шаги 1+2. Для этого готовится автоматическое исправление.
Отключите "Start with Windows" в Afterburner на время экспериментов с UV.
Пока вы подбираете undervolt, AB не должен автоматически запускаться вместе с Windows. Причина: если активен нестабильный профиль, AB применит сломанный UV-профиль сразу после загрузки, раньше чем вы успеете открыть NV-UV и откатить его. Это может привести к boot loops или сбросам драйвера ещё до входа в систему.

В Afterburner: Settings (⚙) → вкладка General → снимите флажок Start with Windows. Включайте его обратно только после того, как UV-профиль подтверждён как стабильный и вы действительно хотите применять его постоянно.
Отключите блокировку профиля AB (иконка 🔒 lock).
Если слот профиля в Afterburner заблокирован через иконку 🔒 lock, NV-UV не сможет записывать в этот слот. Apply-UV и scanner будут молча завершаться неудачей или зависать. Иконка замка рядом со слотом профиля (1–5) должна быть открыта, пока вы используете NV-UV.
3
Extract + run NV-UV
Распакуйте в любую папку, например C:\NV-UV\, и дважды нажмите NV-UV.exe (права администратора не нужны).
🔗 Первый запуск, Connection Wizard:
NV-UV нужна реальная VF-кривая вашей GPU. При первом запуске:
1. Откройте Afterburner, все sliders должны быть в default (без OC/UV)
2. Нажмите 💾 Save в Afterburner
3. Выберите profile slot (1–5)
4. NV-UV автоматически определит кривую

Это разовая настройка. NV-UV сохранит кривую локально.
🔄 Рекалибровка (Toolbar):
Полный reset: автоматически создаёт backup профилей AB, удаляет только GPU-specific profiles и cache NV-UV, затем перезапускается. Overlay settings, fan curves и другие настройки AB сохраняются. При активном Blackwell hotspot: первое нажатие удаляет hotspot fix через контролируемый rollback и перезапускает NV-UV; только второе нажатие запускает настоящую калибровку. После успешной калибровки hotspot можно установить для нового профиля. Правый клик по кнопке открывает папку с автоматическими backup профилей AB.

🌡️Экспериментальная hotspot-температура Blackwell

На поддерживаемых GPU NVIDIA GeForce RTX 50 появляется отдельный переключатель Hotspot. После явного подтверждения NV-UV устанавливает необходимый monitoring-плагин в MSI Afterburner и автоматически изменяет требуемые конфигурационные файлы.

Отображение

После успешной проверки датчика hotspot-температура появляется в обычной области телеметрии NV-UV. Hotspot-сенсоры, уже предоставляемые MSI Afterburner на более старых поколениях GPU, также могут отображаться там; автоматическая установка плагина ограничена поддерживаемыми Blackwell GPU.

Экспериментальное показание: Отображаемое значение официально не подтверждено. Его нельзя использовать как основание для гарантийных или RMA-обращений, а также для изменений или модификаций видеокарты. Более высокая hotspot-температура по сравнению с другими показаниями сама по себе не означает дефект или ограничение функциональности видеокарты.

Постоянные данные восстановления

Manifest, backups, состояние transaction и обнаруженные идентификаторы GPU/profile хранятся в %ProgramData%\NV-UV\BlackwellHotspot\. Активные установки, созданные старыми версиями NV-UV, при первом запуске автоматически переносятся из %LocalAppData%\NV-UV\hotspot\. Поэтому данные для безопасного rollback сохраняются, даже если обычная папка пользовательских данных NV-UV удалена.

Рекалибровка и создание профиля

Активный hotspot fix может мешать MSI Afterburner заново создать hardware profile. Поэтому Рекалибровка не запускается сразу при активном hotspot: NV-UV сначала требует контролируемое удаление, перезапускается и начинает настоящую калибровку только после второго нажатия Рекалибровка. После завершения предлагается снова установить hotspot для нового профиля.

Смена GPU или VBIOS: После смены Afterburner может создать профиль с другим SUBSYS. NV-UV записывает эту идентичность и не восстанавливает удалённый старый hardware profile из hotspot backup.
Осиротевшая установка: Если обнаружены следы hotspot, но отсутствует manifest или исходные backups, NV-UV не может безопасно угадать предыдущие значения Afterburner. Рекалибровка блокируется, и рекомендуется чистая переустановка MSI Afterburner.

🚀Быстрый старт

1
Выберите preset: 🍃 Эко · ⚡ Баланс (рекомендуется) · 🚀 Перф · 🔥 Max
2

⚠ Нижний порог напряжения Blackwell (RTX 50): примерно на 875 mV и ниже драйвер Blackwell не удерживает V-Лок — он снова бустится к более высокой точке напряжения, поэтому undervolt не закрепляется как задано (lock на 845 mV в итоге работает выше, чем вы выбрали). Для стабильного lock на Blackwell выбирайте выше 875 mV. При этом значении и ниже NV-UV показывает подсказку прямо во вкладке V-Лок. Это поведение драйвера, инструмент не может его обойти.

🔬OCS → UV Import

Встроенный OC Scanner в Afterburner проверяет, насколько дополнительную частоту ваша GPU выдерживает на каждом напряжении. Сам по себе результат очень консервативен. NV-UV берёт эти данные конкретного чипа и объединяет их с проверенным preset Balanced как базой. Результат — UV-кривая под ваш silicon.

1
Запустите AB OC Scanner, сохраните результат в profile slot (1–5).
2
Нажмите OCS → UV, выберите профиль с результатом scanner.
3
Apply: V-Лок (лучшая одиночная точка) или Multi-Point (полная кривая).

Правый клик открывает варианты: V-Лок / Multi-Point / Verify with Scanner.

Данные OCS хранятся постоянно и сохраняются после Рекалибровка, сбросов AB и переустановок.

⚡Сканер шага напряжения

Scanner тестирует одну точку напряжения и находит максимальную стабильную частоту. Это удобно для проверки UV-настройки или поиска оптимум конкретной GPU.

1
Open Scanner (кнопка ⚡ в главном окне или Мини-вид)
2
Settings: Voltage, render resolution (1440p для 5070/5080, 4K для 5090), test duration (2–5 мин)
3
Запустите тест: кнопка ⚡ Начать сканирование (Start test). Scanner начинает с высокой частоты и идёт вниз, пока не найдёт стабильную частоту.
4
Apply result в slot 1–5 напрямую или через правый клик в history.

🎯 Stage 2 — Optimize Point (Новое в Cantor)

Stage 1 находит самую высокую стабильную частоту при заданном напряжении. Stage 2 работает наоборот: начиная со стабильной точки, NV-UV ищет минимальное напряжение, при котором эта частота всё ещё удерживается. Так можно выжать ещё 10–30 mV без потери частоты.

Двухшаговый workflow:

1
Run Stage 1: выберите напряжение (например, 910 mV), запустите scanner и дождитесь стабильной точки. Результат автоматически попадёт в history.
2
Start Stage 2: правый клик по стабильной записи в history → 🎯 Optimize Point. NV-UV тестирует ту же частоту, снижая напряжение шагами по 5 mV до сбоя, затем оставляет последнее стабильное значение.

Пример: Stage 1 находит стабильную точку 2992 MHz @ 910 mV. Затем Stage 2 пробует 2992 MHz @ 905 / 900 / 895 / 890 mV, пока GPU не даст сбой. Если 895 mV было последней стабильной точкой, вы получаете ту же производительность при напряжении на 15 mV ниже — меньше ватт, меньше нагрев, та же частота.

Когда Stage 2 имеет смысл? Когда вы хотите получить максимум именно из своей GPU. Stage 1 — хорошая отправная точка, Stage 2 — тонкая доводка. В зависимости от test duration Stage 2 занимает ещё 5–15 минут.

🎯 Expandable Optimize History (Новое в Cantor)

Раньше NV-UV сохранял только одну точку, выбранную вами в диалоге optimize result; все остальные измеренные voltage probes удалялись после закрытия диалога. Это особенно мешало, когда слишком агрессивный undervolting приводил драйвер к сбою render-thread, а окно выбора переставало отвечать: все измерения терялись, Stage 2 приходилось начинать заново.

Начиная с v0.126, NV-UV записывает полный optimize run в history до показа окна выбора. После этого в history появляется новая запись с маркером 🎯, где все probes из прогона сохранены как раскрываемые sub-entries:

▶
Collapsed (по умолчанию): одна компактная строка-заголовок на каждый optimize run, например 🎯 from 925 mV · 11 probes · clean или после сбоя 🎯 from 985 mV · 9 probes · TDR @ 935 mV. Нажмите заголовок, чтобы раскрыть.
▼
Expanded: каждый измеренный probe прогона показывается как вложенная запись, с напряжением, median clock под нагрузкой и отметкой ✓ на том probe, который вы изначально выбрали. Каждый sub-entry можно использовать отдельно: правый клик → apply to slot, verify или re-optimize. Конечная точка TDR, если она есть, отображается строкой 💥 в конце и носит только информационный характер.

Почему это важно: если после окна выбора вы понимаете, что выбранная точка слишком агрессивна, не нужно заново запускать поиск — просто раскройте группу и выберите один из более консервативных probes (например, на 5 или 10 mV выше). А если driver crash убьёт NV-UV посреди прогона, вся группа со всеми probes всё равно останется после перезапуска.

🔍 Verify Point

Правый клик по записи history → Verify запускает расширенный stress test с этой точной парой frequency/voltage. Используйте это, чтобы дополнительно проверить результат Stage 1 или Stage 2 более длинным прогоном (например, 10 минут вместо 3), прежде чем записывать его в slot.

🧪 VRAM-only Test

В окне scanner: кнопка 🧪 VRAM-only Test. Она фиксирует core на stock и тестирует только заданный VRAM offset. Полезно, когда нужно изолировать источник сбоя: VRAM OC или core UV. Сначала зафиксируйте core на проверенном значении, затем отдельно разгоняйте VRAM.

🎮Игровой Реплей

Просто играйте — Игровой Реплей сделает остальное. При UV crash частота автоматически снижается.

Learning Loop

Игровой Реплей теперь запоминает корректировки после сбоев отдельно для каждой игры. При следующем запуске той же игры UV-Пилот автоматически применит сниженную частоту. Игра падает один раз — в следующий раз сразу загружается безопасный профиль.

Per-Profile History

Истории сбоев теперь отслеживаются по комбинации game + profile. Раньше, например, сбой Performance-tier в игре мог переноситься и на Custom profile, назначенный позднее. Начиная с v0.94, у каждого profile (Eco / Balanced / Performance / Max / Custom XYZ) своя чистая история. Custom profile больше не наследует сбои от presets.

При первом запуске v0.94 существующий nv-uv_game_replay_adjustments.json определяется как старый формат и один раз очищается (warning в log: "Old adjustment format detected — discarded"). После этого history перестраивается по профилям. Ручных действий не требуется.

Manual applies (клик по slot-button без UV-Пилота) по-прежнему не сохраняются: при crash live downstep применяется, но JSON-запись не создаётся, потому что без контекста Pilot её нельзя однозначно привязать к профилю.

Обзор Replay Adjustments (Новое в v0.99.2)

В Game Browser появилась отдельная вкладка Replay Adjustments. Она показывает игру и процесс, tier или custom profile, исходное и скорректированное значения, количество обнаруженных сбоев и время последнего сбоя.

Отдельные корректировки можно сбросить прямо в списке. Кнопка Reset All после подтверждения очищает всю историю корректировок Игрового Реплея. Обзор также открывается напрямую правым кликом по переключателю Game Replay в главном окне или MiniWindow.

ТипЧто происходит

Settings

Переключатель 🎮 Replay на toolbar, правый клик — settings. Strategy: снижать частоту (default), повышать напряжение или делать оба действия. Step sizes и safety limits настраиваются, с v0.99 frequency step можно уменьшить до 15 MHz (аппаратно-нативный шаг V/F-таблицы).

Игровой Реплей работает независимо от UV-Пилота. Просто включите 🎮 Replay — он работает с любым активным UV profile.

Правый клик по UV-Пилот → "📐 Мини-вид on Gaming". При обнаружении игры автоматически переключает в Мини-вид, снижая GPU overhead от главного окна WPF. По умолчанию отключено.

Foreground Priority

Начиная с v0.94, UV-Пилот отдаёт приоритет процессу окна, которое сейчас в фокусе. Это решает ситуацию, когда одновременно запущены две или более записи из game database, обычно browser + game.

Раньше: открыт Chrome (Eco tier), вы запускаете игру → Chrome-Eco profile остаётся активным, пока Chrome полностью не закрыт.
Теперь: как только игровое окно получает фокус, Pilot определяет переключение и применяет соответствующий game profile. Обратное переключение работает так же — Alt-Tab в Chrome переключает на Eco, Alt-Tab обратно в игру — на Performance.

Fallback: если foreground process не является записью DB (Explorer, Desktop и т.п.), Pilot сохраняет текущий lock. Поэтому Alt-Tab на рабочий стол не сбрасывает gaming lock.

⚓Anchor Profile

Anchor profile — это ваш "home slot". Он определяет, какой UV profile NV-UV должен автоматически загружать в двух ситуациях: при запуске программы и после завершения игры.

Настройка

Правый клик по слоту с сохранённым UV profile → ⚓ Set as Anchor. Слот получит маркер ⚓ и будет подсвечен в slot overview.

Поведение подробно

СитуацияЧто происходит
Запуск программыNV-UV обнаруживает anchor profile и автоматически загружает его при старте. Работает и без UV-Пилота, удобно для setups с Windows autostart.
После завершения игрUV-Пилот определяет выход из игры и восстанавливает anchor profile вместо возврата к предыдущему слоту. Требуется активный UV-Пилот.

Практический пример

Ваш daily UV находится в Slot 1 (например, 2902 MHz @ 950 mV), и вы назначаете его как Anchor. При загрузке Windows NV-UV запускается через autostart, AB стартует, и Slot 1 сразу активен — клики не нужны. Когда вы запускаете игру, которую UV-Пилот связывает с tier "Max", Pilot кратковременно переключается на Slot 4. После завершения игры он возвращается в Slot 1 (Anchor), а не к предыдущему состоянию.

Совет: Stock anchor тоже работает. Если назначить пустой slot как anchor, NV-UV загрузит stock values при старте. Anchor — явная "home"-директива, а не подсказка "только для UV".

🔧Дополнительные функции

🧊 Оптимизация простоя

Устанавливает все точки напряжения ниже 850 mV на stock frequency. Экономит питание на рабочем столе/в idle.

🔧 Фикс V-шага

Компенсирует Blackwell-ошибку point-before-flatten. Под нагрузкой GPU использует точку напряжения перед lock (~на 10 mV меньше). Фикс V-шага компенсирует это автоматически.

Применяется к: Быстрый Лок в главном окне (режим V-Лок). Доступен как checkbox рядом со slider напряжения.

📐 V-Step Compensation (Новое в Cantor)

В окне scanner есть собственный checkbox V-Step Compensation. Он делает не то же самое, что описанный выше Фикс V-шага, поэтому ниже прямое сравнение:

Функция Где Что делает
🔧 Фикс V-шага Главное окно
(при применении V-Лок)		 Сдвигает lock point вверх на один VF step, чтобы под нагрузкой GPU не проваливался в точку перед ней.
📐 V-Step Compensation Окно scanner
(во время scan)		 Постоянно измеряет разницу между запрошенным напряжением и напряжением, фактически доходящим до чипа (V-Droop), и корректирует следующие test steps.

Когда это стоит включать? Когда вам нужны точные напряжения в scanner. Пример: вы запрашиваете 910 mV, но MAHM сообщает 905 mV — дельта 5 mV добавляется внутри, чтобы следующие test steps реально попадали в 910 mV на чипе, а не только в 905. Это делает scan results намного более воспроизводимыми, особенно при использовании Stage 2 (Optimize Point), где важен каждый millivolt.

Полностью автоматическая функция, работает тихо в фоне. В log будут строки вроде [VDroop] adapted: req 910 mV → MAHM 905 mV (Δ+5) → comp 5 mV. Включена по умолчанию.

🔋 Power Limit

Slider ограничивает максимальное энергопотребление. Eco presets задают сниженный PL, MFG / Performance / Max — 100%.

💾 VRAM Offset

Offset частоты памяти. Default: 0 MHz. GDDR7 редко получает заметную пользу от memory OC.

🔓 Override Safe Limit

Убирает safety margin 50 MHz ниже stock maximum. Только для опытных пользователей.

🖥 UI Scaling

Кнопка % в footer. Шаги: от 100% до 300%. Все окна масштабируются вместе.

🖥Смарт Hz

Автоматически переключает рабочий стол на низкую частоту обновления, когда игра не запущена, и возвращает native rate при запуске игры. Экономит примерно 10–25 W в idle. Toggle находится на toolbar.

Выбор idle rate (новое): правый клик по кнопке Смарт Hz позволяет выбрать одну из частот обновления, которые реально поддерживает монитор (например, 60 / 120 / 144 Hz). Выбор частоты сразу активирует Смарт Hz, поэтому отдельно включать toggle не нужно. Выбранная частота сохраняется между перезапусками.

Может вызывать проблемы в multi-monitor setups. Если сомневаетесь — оставьте выключенным. Для определения игр требуется UV-Пилот.

⚡UV⚡Проба (Community UV Database)

UV⚡Проба открывает browsable database community undervolt values для вашей GPU, сгруппированную по Eco, Balanced и UV+OC. Каждая entry показывает voltage, clock, power limit, VRAM offset, board, confidence label и source link. Список заранее выбирает обнаруженную карту.

Открывается кнопкой UV⚡Проба рядом с presets (Eco / Bal / Perf / Max). Чтобы применить значение, нажмите правой кнопкой по entry и выберите profile slot (1–5), как в scanner history.

Rating и community-votes (НОВОЕ в v0.99): Клик по звезде делает и то и другое: сохраняет вашу личную пометку локально и одновременно считается анонимным community-vote. Новая колонка Community показывает средний балл всех голосов с количеством в скобках, например "★ 4.2 (17)", и обновляется два раза в день. Повторный клик по той же звезде (0 звёзд) удаляет ваш голос и на сервере.

Отправка собственных настроек (НОВОЕ в v0.99): Правый клик по занятому profile slot → Share to Community DB. Значения берутся из слота как есть (то есть реально проверенный профиль), опциональны только вариант платы и короткая заметка. После короткой проверки ваш preset появляется у всех в UV⚡Пробе с пометкой "user-submitted". Подробнее о передаваемых данных — в разделе Community-функции и данные.

Community values — только отправная точка. Каждая карта отличается (silicon lottery), поэтому всегда проверяйте значение на собственной карте, прежде чем на него полагаться.

🔒Community-функции и данные

В NV-UV нет аккаунтов, нет телеметрии и никакой автоматической отправки данных. Данные передаются только тогда, когда вы сами используете одну из двух community-функций:

Оценка звёздами в UV⚡Пробе: При клике по звезде оценка сохраняется локально и дополнительно отправляется анонимный community-vote. Передаются только: preset ID, ваша оценка и случайный client ID (случайный GUID, создаваемый локально, без какой-либо привязки к железу или личности). Повторный клик по той же звезде (0 звёзд) удаляет ваш голос и на сервере.

Отправка настроек (правый клик по слоту профиля): Передаются UV-значения из слота (частота, напряжение, при наличии power limit и VRAM offset), определённая модель GPU, опционально вариант платы и короткая заметка, а также тот же случайный client ID. Важно: После одобрения эти данные становятся публично видимыми в community-базе на GitHub. Не пишите личную информацию в заметку.

Техническое: Как и любой интернет-сервис, сервер (Cloudflare Worker) видит ваш IP-адрес. Он обрабатывается исключительно как ежедневно пересаливаемый хеш для защиты от злоупотреблений и никогда не сохраняется в открытом виде. Отображение community-оценок, обновление базы и проверка обновлений при запуске (раз в день загружается с GitHub информация о том, вышла ли новая версия NV-UV) — это обычная загрузка с GitHub, при этом ничего не отправляется. Случайный client ID лежит в %LocalAppData%\NV-UV\nv-uv_client_id.txt и может быть удалён в любой момент (при следующем голосе создаётся новый).

🌍Global Override & No Override

В Game Library можно задать Global Override (dropdown на toolbar): он принудительно назначает всем запущенным играм выбранный tier (Eco / Bal / Perf / Max), перекрывая индивидуальные назначения. Удобно, если вы используете только UV-Пилот и хотите один tier везде.

No Override исключает отдельную игру из global override — тогда она определяется обычным способом (собственный tier, tier из database или stock). Задаётся либо через per-game override dropdown ("⊘ No Override"), либо правым кликом по строке игры. Полезно для записей вроде browser, которые вы не хотите трогать через UV-Пилот.

📐Мини-вид

Компактный вид без кривой. 📐 Mini на toolbar, ↩ Full — возврат. Всегда поверх окон. Доступны все функции: Slots, Presets, V-Лок, PL, VRAM, Scanner, OCS → UV.

Performance tip: главное окно использует WPF rendering, который может измеримо снижать GPU performance в benchmarks. Во время игр или benchmark лучше использовать Мини-вид либо свернуть NV-UV в tray. Мини-вид имеет значительно меньший rendering overhead.

Auto-Mini on Gaming

Правый клик по UV-Пилот → "📐 Мини-вид on Gaming" включает автоматическое переключение в Мини-вид при обнаружении игры. После выхода из игры возвращает full view. По умолчанию отключено.

❓FAQ

Заменяет ли NV-UV Afterburner?

Нет. NV-UV использует Afterburner как backend. AB должен быть установлен. Для OC, OSD и расширенного редактирования кривой AB остаётся основным инструментом.

Безопасен ли undervolting?

Напряжения не повышаются, а только снижаются. Всё можно сбросить через кнопку ⟲ Сток (Stock) или Рекалибровка. Однако автор не несёт ответственности за любой ущерб, который может прямо или косвенно возникнуть из-за undervolting.

Почему NV-UV не показывает напряжение? (0 mV / no reading)

Это самая частая проблема при настройке. Причина: voltage options не включены в Afterburner. NV-UV читает напряжение через shared memory Afterburner (MAHM), и без правильных настроек AB MAHM просто ничего не возвращает.

Быстрая проверка: посмотрите на главное окно Afterburner. Поле "VOLT" тоже показывает 0 mV? Значит, сам AB тоже не читает напряжение — проблема в AB, а не в NV-UV. Исправление:

  1. AB → Settings (⚙) → вкладка General → Unlock Voltage Control ✓ и Unlock Voltage Monitoring ✓
  2. AB → Settings (⚙) → вкладка Monitoring → прокрутите вниз и включите GPU voltage ✓
  3. Нажмите OK (не Cancel) и полностью перезапустите Afterburner
  4. Главное окно AB теперь должно показывать реальное значение в "VOLT" (например, 905 mV). Только после этого NV-UV тоже сможет видеть напряжение.

Подробное пошаговое описание со всеми рекомендуемыми флажками: см. выше Installation → Steps 1 + 2.

Примечание для Reference-Design RTX 5090: на некоторых картах Afterburner иногда сам сбрасывает флажки Unlock. Если показания напряжения через некоторое время исчезают, просто повторите шаги 1+2.

Почему напряжение под нагрузкой ниже моей цели V-Лок?

Это нормальное поведение GPU boost. NV-UV задаёт V-Лок, например на 950 mV, но GPU бустится только до того напряжения, которое нужно с учётом температуры и power limits. При UV profile (кривая выровнена на lock point) нет смысла буститься выше. Это не bug.

Почему scanner останавливается ниже моего stock maximum?

Возможны две причины:
1. Safe Limit: по умолчанию scanner останавливается на 50 MHz ниже stock max. Включите "Override Safe Limit", чтобы убрать это ограничение.
2. Driver Limit: NVIDIA ограничивает frequency offset значением +1000 MHz на каждую точку напряжения. Решение: тестируйте на более низком напряжении, где остаётся больше headroom.

Scanner продолжает повышать шаги, но частота GPU не растёт

Исправлено в Antares. Plateau detection автоматически останавливает scanner, когда GPU уже не может буститься выше. Если у вас более старая версия — обновитесь до Antares.

Игра падает после UV, что делать?

Это нормально: не каждая GPU выдерживает каждый preset. Попробуйте следующий более высокий preset или используйте scanner для индивидуальной оптимизации. С Игровой Реплей можно просто продолжать играть: частота снижается автоматически — в идеале прямо во время игры или после сбоя при следующем запуске.

Разница между V-Лок и Multi-Point?

V-Лок фиксирует GPU в одной точке напряжения/частоты. Простой, надёжный и рекомендуемый метод.
Multi-Point задаёт несколько точек на кривой (например, из OCS Import). Сложнее, но потенциально эффективнее по всему диапазону напряжений.

Почему EXE около 200 MB?

Self-contained .NET 10 runtime. Установка не нужна, просто запускаете EXE.

Поддержка Windows 10?

Не планируется. Для DXR stress testing требуется Windows 11.

Поддержка RTX 40 series?

Полностью поддерживается. Начиная с "Ada improved" (v0.94), активен native Ada write path. Byte-exact curve encoder проверен на KFA2 RTX 4070 Ti (AD104) и работает по всей цепочке — Apply, Scanner, Игровой Реплей и UV-Пилот. Preset values (цели frequency/voltage) основаны на community data; особенно нужны тестеры Ada с RTX 4090 (AD102) и RTX 4080 / 4080 Super (AD103), чтобы уточнить per-chip constants — пишите на PCGH forum или Discord. RTX 4060 Ti (AD106) и RTX 4060 (AD107) также поддерживаются с experimental preset values из AI-DeepSearch research; тестеры с этими картами тоже приветствуются.

Почему Boost Override / Фикс V-шага / Оптимизация простоя отсутствуют на картах Ada?

Это компенсации, специфичные для Blackwell:

  • Boost Override (+1200 MHz вместо +1000 MHz) применяется только к Blackwell XOC cards (Lightning / Matrix / HOF).
  • Фикс V-шага компенсирует point-before-flatten bug в кривой Blackwell.
  • Оптимизация простоя опирается на Blackwell fantasy-frequency encoding.

Ada использует полностью отдельный UV path (native 4-zone curve), которому не нужны эти три компенсации. Поэтому checkboxes автоматически скрываются на картах Ada и в главном, и в mini view.

Почему NV-UV снижает benchmark points?

Главное окно WPF использует ресурсы GPU для rendering и DWM compositing. В 3DMark это может стоить около 200–500 points. Решение: используйте Мини-вид, сверните NV-UV в tray или включите Auto-Mini on Gaming (правый клик по UV-Пилот). Ваш UV profile остаётся активным в AB даже когда NV-UV свёрнут или закрыт.

Antivirus flags NV-UV

False positive. Self-contained .NET SingleFile EXE иногда помечаются антивирусами. NV-UV безопасен, можно добавить исключение.

Где хранятся мои настройки?

%LocalAppData%\NV-UV\ содержит UV profiles, slot names, Игровой Реплей adjustments, scanner history, OCS data, stock curve, CCB cache и logs.

Постоянные данные восстановления экспериментального Blackwell hotspot хранятся отдельно в %ProgramData%\NV-UV\BlackwellHotspot\. Не удаляйте эту папку вручную, пока hotspot активен.

Как экспортировать log files?

Используйте кнопку Log Export под log panel. NV-UV создаёт diagnostics ZIP с activity.log, activity-previous.log, diagnostic.log, diagnostic-previous.log и system-info.txt. Этот ZIP можно напрямую отправить Christian.

Помогите, мои profiles исчезли!

Всегда вручную делайте backup профилей перед экспериментами. Если profiles потеряны: проверьте папку NV-UV в %LocalAppData%\NV-UV\, там хранятся saved data, OCS curves и scanner history.

Мой ПК плохо загружается после нестабильного UV!

Важный совет при экспериментах с UV: в Afterburner в Settings → General отключите Start with Windows. Это не даст нестабильному профилю автоматически загрузиться при старте, если UV-настройка валит драйвер во время запуска. Включайте AB autostart обратно только после того, как UV-настройка подтверждена стабильной в играх.

🛠Устранение неполадок

NV-UV запускается, но не показывает GPU

Установлен последний драйвер NVIDIA? Запускайте NV-UV после полной загрузки рабочего стола Windows.

Нет соединения MAHM (нет показаний напряжения)

AB + RTSS должны быть запущены. Включите voltage monitoring в AB (см. FAQ выше). Перезапустите AB.

Показания напряжения скачут или выглядят некорректно

В AB: Settings → Monitoring → Active hardware monitoring graphs, отключите plug-ins GPU.dll и HwInfo.dll. Они параллельно обращаются к тем же GPU sensors, которые NV-UV использует через MAHM, что вызывает конфликтующие sensor reads. В итоге MAHM лишь эпизодически возвращает валидные значения (напряжение скачет, показывает 0 или нереалистичные числа).

Спасибо Martin с PCGH forum за эту находку.

Apply ничего не делает / напряжение не меняется

Включите Unlock Voltage Control в AB. Нет stock curve? Нажмите 🔄 Рекалибровка. Если Blackwell hotspot активен, fix сначала удаляется через контролируемый rollback, и только затем начинается настоящая калибровка.

Игра падает после UV

Попробуйте более высокий preset или используйте scanner. Игровой Реплей снижает частоту автоматически.
